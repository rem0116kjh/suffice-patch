# 외부 저장소 평가 사전 계획 — 2026-10-06

## 검증할 주장

최종 SufficePatch가 작은 공개 Python 라이브러리의 국소적인 유지보수에서
정확성을 유지하며 에이전트의 탐색 토큰을 줄이는지 확인한다. 속도, 도구 이벤트,
캐시를 제외한 입력, 출력은 각각 별도로 판단한다. 실사용자 효과, 대규모 저장소,
다른 언어, 다른 모델, Linux/Windows의 효과까지 검증했다고 말하지 않는다.

- 각 과제에서 baseline/자동 선택을 각각 3회: 12쌍, 총 24회.
- 난수 시드 20261006으로 과제·반복 쌍의 순서를 고정하고, 각 쌍 안의 실행 순서는
  반복과 과제에 따라 교차한다. 모델 실행은 순차적으로 수행한다.

- 전역 설치·설정을 변경하지 않는다. 플러그인, 훅, 앱, 메모리, 웹 검색,
  하위 에이전트는 평가 호출에서 비활성화한다.
- 상위 저장소의 정답·수정 이력·숨은 검사기는 작업 체크아웃에 제공하지 않는다.
  각 실행은 원본 커밋의 archive에서 만든 새 Git 저장소를 사용한다.
- 모델 응답의 self-report가 아닌 별도 프로세스의 숨은 행동 검사와 기존 upstream
  테스트, 보호 파일 비교를 성공 조건으로 사용한다.
- 개별 실행 한도 300초. 실패·시간초과·스킬 미선택 결과도 그대로 집계한다.
  유리한 결과를 얻기 위한 재실행이나 과제 교체는 하지 않는다.
- 인프라 실패가 연속 2회 발생하면 나머지 모델 호출을 중단하고 미실행 수를 명시한다.
  이미 종료한 시도는 재실행하지 않는다. 실제 코드 수정 실패는 인프라 실패가 아니다.

## 판단 기준

1. 정확성: 자동 선택의 전체 성공 수와 과제별 성공 수가 baseline보다 낮지 않아야 한다.
   성공에는 숨은 검사, 기존 테스트, 보호 파일·스킬 보존이 모두 필요하다.
2. 토큰 개선: 각 과제의 3개 paired token ratio 중앙값을 구하고, 4개 과제에 같은 가중치를
   둔 기하평균이 0.90 이하여야 한다. 과제 단위 재표집한 95% bootstrap 구간의 상한도
   1.0 미만이어야 제한된 표본에서 토큰 개선을 지지한다고 판정한다.
3. 시간 개선은 같은 방식으로 별도 판정한다. 기하평균이 0.95 이하이고 구간 상한이
   1.0 미만이어야 한다. 도우미의 실행 시간과 전체 에이전트 경과 시간을 혼동하지 않는다.
4. 비용은 직접 측정하지 않는다. 총 토큰, cached input, uncached input, output을 공개하며
   어떤 결과에서도 실제 청구 금액 감소를 입증했다고 말하지 않는다.
5. baseline의 스킬 사용이나 사전 활성화 검사 실패는 비교 무효로 표시한다.
   자동 선택 조건에서 스킬을 선택하지 않은 경우는 배포 정책의 결과로 포함한다.

bootstrap은 시드 20261006, 10,000회, 과제별 중앙값 4개를 복원 추출한다. 동일 프로젝트의
두 과제는 독립적이지 않으므로 프로젝트 단위로 묶은 보조 구간도 제공한다. 작은 수의
편의 표본에 대한 기술적 구간이며 사용자 모집단의 통계적 보장을 뜻하지 않는다.

## 공개와 한계

원시 이벤트, 모든 실패, 사전 계획, 고정 manifest, 숨은 검사, 변경 diff, 집계 코드를 함께
남긴다. README의 설명은 관측 결과에 맞춘다. 기준을 충족하지 않으면 미충족으로 결론낸다.

과거 공개 수정은 모델 학습 데이터에 포함되었을 가능성이 있다. 정답 텍스트를 주지 않더라도
이 오염 가능성을 제거할 수 없다. 요청에서 수정 위치를 알려 주며 국소적인 Python 과제로
범위가 제한된다. 같은 컴퓨터·Codex 설정에서 얻은 반복 결과는 다른 사람의 실제 사용 후기나
크로스 플랫폼 시험을 대신하지 않는다.

단일 파일 예제를 넘어 실제 전체 저장소를 사용하지만, 저장소 규모는 46–84개 추적 파일과
16–31개 Python 파일이다. 대형 저장소의 효율을 주장할 근거로 사용하지 않는다.
