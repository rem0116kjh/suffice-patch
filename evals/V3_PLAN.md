# SufficePatch v3 검증 계획

2026-10-03 사용자 요청으로 효율 개선 작업을 다시 시작한다. 과거 v2 결과와
종료 기록은 해당 버전의 역사 자료로 보존한다.

가설: 이미 파일이 지정된 작은 유지보수에서 별도 위치 확인을 생략하고,
확인·수정·검증의 불필요한 모델 왕복을 줄이면 지침 처리 비용보다 큰 이득이 난다.
정확성·권한 검사·데이터 보존·필수 프로젝트 검사는 줄이지 않는다.

1. 별도 v3 후보를 동결하고 기존 `reuse`, `atomic` 두 과제를 baseline과 각 1회 비교한다.
   성공률이 같고 합계 tokens가 10% 이상 낮으며 tool calls가 늘지 않을 때 다음 단계로 간다.
2. 후보를 바꾸지 않고 새 네 과제를 조건별 두 번씩 실행한다. baseline/v3 순서를 회전한다.
   실행 실패·timeout도 분모에 포함한다. 목표는 모두 통과, 합계 및 median tokens 각각
   10% 이상 감소, 합계 tool calls 비증가다. 이는 실용적 채택 기준이며 통계적 유의성 기준이 아니다.
3. 목표를 충족하면 실제 설치 경로의 native 호출도 확인하고 설치본을 갱신한다.
   native 선택·로딩 비용, 모델 및 범위 차이를 별도로 명시한다.

첫 실험이 실패하면 원인을 확인해 좁은 수정 한 번만 허용하고, 새 후보와 재시도는
기존 기록을 덮어쓰지 않는다. 반복 최적화로 유리한 결과만 고르지 않는다.
이번 작업은 작은 유지보수 범위이며 대형 프로젝트·모든 모델의 효율을 보장하지 않는다.

## 기계적 도우미로의 변경

v3와 한 번 보정한 v3-1은 모두 source-only workflow 후보로 보존한다.
v3는 2/2 성공을 유지했지만 tokens가 3.86% 늘었다. v3-1도 관련 모듈 읽기와
추가 caller 탐색을 나눠 실행했다. 지침 문장 보정은 여기서 중단했다.

이 관측에 따라 이후 후보는 Python 유지보수에 한정한 읽기 전용 context 도우미를
포함한다. 후보·runner·원자료 경로는 `v3-tools`로 분리하고 앞선 실패를 포함해 보고한다.
도우미는 원본 source와 로컬 import, 텍스트로 일치한 호출부/테스트, AGENTS.md,
Git 변경을 한 실행에서 반환한다. 소스 파일을 실행하거나 수정하지 않는다.

외부 경로/심볼릭 링크 거절, 내용·파일 개수 한도, 상대 import, 원본 보존 검사를
먼저 수행한다. 이후 기존 두 과제로 한 번 비교하고 같은 10% gate를 적용한다.
통과하면 이미 동결한 네 새 과제 × 2회 비교와 native 호출 비교로 진행한다.
도우미도 비용 목표에 실패하면 설치하지 않고 실패와 한계를 그대로 보고한다.

Native 비교는 사용자 전역 설치를 건드리지 않는 별도 repo skill에서 수행한다.
기본 조건에서는 해당 repo skill과 기존 사용자 skill을 모두 비활성화하고,
명시적/자동 호출 조건에서는 repo skill만 켠다. 자동 호출의 본문 읽기 비용도 포함한다.

## 최종 자동 선택 결정

최초 native 비교에서는 명시 호출이 절감되었지만 자동 선택은 tokens가 2.77% 늘었다.
사용자가 자동 선택 유지를 명시적으로 선택하여 description에 읽기 전용 진입점을
노출한 별도 `v3-autoload` 후보를 동결하고 두 과제 × 두 반복으로 native 비교했다.
결과는 [V3_RESULTS.md](V3_RESULTS.md)에 모두 기록한다. 최종 자동 선택의 tokens는
21.10% 줄었지만 도구 이벤트는 16→19로 늘어 호출 비증가 목표는 달성하지 못했다.
사용자 선택과 토큰 절감을 근거로 이 tradeoff를 명시하여 설치했으며, 사전 gate를
모두 통과한 것으로 소급해서 바꾸지 않는다.
