**24회 평가에서 두 조건 모두 12/12 성공했고, 자동 선택 조건은 사전 시간 개선 기준을 충족했다. 토큰 개선 기준은 충족하지 못했다.** 과제별 반복쌍 중앙값을 동일 가중으로 집계한 주지표에서 시간은 24.7% 줄었고 총 토큰은 20.4% 늘었다. 이 결과는 지정한 소형 Python 과제·호스트·모델에서의 관측이며 다른 사람에게 같은 효과를 보장하지 않는다.

## 실제 upstream 과제와 채점 대조

임의로 삽입한 버그 대신 공식 저장소의 실제 과거 base와 수정 커밋을 복제했다. 프롬프트는 수정할 함수·파일과 요구 동작을 알려 주지만, 구현이나 수정 커밋은 알려 주지 않는다. 이 때문에 결과는 위치가 주어진 국소적인 수정 작업에 대한 증거다.

| 프로젝트·과제 | base → 공식 수정 | 고정 base의 추적 파일 / Python 파일 | 외부 채점 대조 |
| --- | --- | ---: | --- |
| python-dotenv: 백슬래시 저장·파싱 | `751f8c1` → `f7b18d9` | 46 / 20 | 25/65 → 65/65 |
| packaging: epoch·wildcard 비교 | `cc0c65c` → `c52d2b3` | 84 / 31 | 125/202 → 202/202 |
| itsdangerous: 잘못된 타임스탬프 오류 | `85b1e3b` → `37f0997` | 57 / 16 | 실패 → 30/30 |
| itsdangerous: 만료 경계, 변경 불필요 | `37f0997` → 동일 | 57 / 16 | 이미 52/52 |

공식 근거는 [python-dotenv issue #661](https://github.com/theskumar/python-dotenv/issues/661) 및 [수정 커밋](https://github.com/theskumar/python-dotenv/commit/f7b18d9c72d1abcc2ad4023424b84f5bee30d266), [packaging PR #712](https://github.com/pypa/packaging/pull/712), [itsdangerous PR #296](https://github.com/pallets/itsdangerous/pull/296)이다. 전체 커밋 해시, 파일 수와 대조 실행 원문은 각 [dotenv](external_tasks/dotenv/provenance.md), [packaging](external_tasks/packaging/provenance.md), [itsdangerous](external_tasks/itsdangerous/provenance.md) 기록에 있다.

외부 채점기는 공개 API의 결과를 검사하며 정답 코드 문자열이나 특정 구현을 요구하지 않는다. 고정 reference를 새 임시 트리에 추출한 독립 대조에서 4과제 모두 통과했고, 대상 소스 파일을 비운 대조에서는 모두 실패했다. 검사 항목 65·202·30·52개는 **각 과제 내부의 확인 항목**이며 독립적인 과제·사용자 수가 아니다.

기존 upstream suite도 보존했다. packaging은 base 26,824개와 reference 26,827개가 통과하고 각각 1개를 건너뛰었다. itsdangerous의 base는 해당 회귀 1개가 실패하고 296개가 통과했으며 reference는 297개가 통과했다. python-dotenv는 사전 제외 1개 외에 base 222개, reference 240개가 통과했다. reference에 추가된 회귀 테스트 때문에 base와 개수가 다르다. 에이전트 수정본에는 각 base의 기존 테스트와 외부 채점을 적용한다.

python-dotenv의 `tests/test_cli.py::test_run_with_command_flags`는 GNU `printenv --version`을 가정해 macOS의 BSD `printenv`에서 base/reference 모두 실패했다. 모델 호출 전에 이 1개만 제외했고 기존 테스트 파일은 수정하지 않았다. 따라서 python-dotenv의 역사적 전체 suite가 macOS에서 전부 통과했다고 주장하지 않는다.

## 사전 통계와 판정 방법

각 반복쌍에서 `자동 선택 / baseline` 비율을 구하고, 과제별 3개 비율의 중앙값을 구한 뒤, 4과제에 같은 가중치를 준 기하평균으로 집계한다. 큰 토큰 과제가 합계 비율을 지배하지 않도록 정한 방식이다. 모든 실패·미선택도 비율과 원시 합계에 남긴다.

정확성 조건은 자동 선택의 전체 성공 수와 **각 과제의 성공 수 모두** baseline 이상인 것이다. 한 과제의 손실을 다른 과제의 이득으로 상쇄하지 않는다. 이 조건을 만족하더라도 토큰과 시간 개선은 각각 판정한다.

- 토큰: 기하평균 비율 ≤ 0.90이며 과제 bootstrap 95% 구간 상한 < 1.0.
- 시간: 기하평균 비율 ≤ 0.95이며 같은 방식의 구간 상한 < 1.0.
- seed `20261006`, 10,000회 과제 단위 복원추출과 percentile 구간을 사용한다. 같은 프로젝트의 두 과제가 독립적이지 않으므로 프로젝트 3개를 묶어 재표집한 보조 구간도 공개한다.
- 미완료, 필요한 측정값 누락, baseline 스킬 사용 등 비교 무효는 긍정적인 효율 판정을 막는다. 자동 선택 조건의 미선택은 정책의 결과이므로 제외하지 않는다.
- 버그 수정 3과제와 변경 불필요 1과제의 성공률·토큰·시간을 별도 공개한다. 도우미 사용률의 분모는 성공 사례만이 아니라 자동 선택 시도 전체다.

측정 시간은 모델 에이전트 프로세스의 경과 시간이다. 도우미 단독 마이크로벤치마크나 외부 채점의 실행 시간과 혼합하지 않는다. 작은 편의 표본의 bootstrap 구간은 이 실행 자료의 기술적 요약이며 사용자 모집단에 대한 통계적 보장이 아니다.

[집계 코드](external_summarize.py)는 개선·악화·정확성 손실·누락·오염·중복 실행·프로젝트 의존성·캐시 중복 합산 방지에 관한 합성 검증 11개를 통과했다. 해당 테스트는 집계 프로그램의 검증이며 스킬의 실제 효과를 측정한 횟수에 포함하지 않는다.

python3 -B evals/runs/generalization-20261006/assets/external_summarize.py \

다음 **원래 실행의 전체 감사**는 평가 호스트의 원래 경로와 workspace가 보존된 경우에 실행한다. 감사 프로그램은 기록된 절대 경로와 실제 candidate 파일을 읽는다. workspace는 Git에 포함되지 않으므로 다른 경로에 원자료만 clone한 상태에서는 이 감사를 그대로 재현할 수 없다.
