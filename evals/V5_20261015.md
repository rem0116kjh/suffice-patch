# SufficePatch v5.0.0 — 2026-10-15

v5는 기존 v4 수집기에 Git 변경 파일 선택, 요약·JSON 출력, 실행 내 언어 분석 캐시를
추가한다. 기본 텍스트 출력과 16파일/40,000바이트 한도를 유지한다. 자동 선택을 끄는
정책은 추가하지 않았다. v3의 모델 토큰 측정은 v5의 성능 근거로 사용하지 않는다.

## 동작과 검증

| 확인 항목 | 결과 |
|---|---|
| Python 3.15 전체 회귀 검사 | 69/69 통과: 기존 수집기 29 + v5 15 + 기존 평가 도구 25 |
| Python 3.12 수집기 호환성 | 44/44 통과 |
| 스킬 형식 검사 | skill-creator의 quick_validate 통과; PyYAML은 별도 임시 venv에만 설치 |
| Git 선택 | staged/worktree/all, 미추적 opt-in, 삭제·이름 변경, 한글·공백·줄바꿈 경로, unborn branch, 중첩 root, scope 확인 |
| 읽기 전용 | Git clean/process/textconv/external diff/fsmonitor 미실행; 작업 파일과 Git index 포함 파일 바이트 보존 |
| 경계·한도 | 외부 symlink 거절, source/candidate 한도, clean repo의 자동 전체 읽기 방지, Git 실패의 비정상 종료 확인 |
| JSON·요약 | 실제 바이트와 SHA256 일치, 전체/요약의 source 목록 동일, 요약에 본문·diff 없음 |
| 캐시 | 10파일 Go 패키지에서 go.mod 읽기 2회 이내; 재호출 후 변경된 파일 내용 반영 |
| 정렬 검색 | 후보 한도 적용 전 경로 정렬; 역순 생성 fixture의 반복 결과 동일 |
| ZIP 재설치 검사 | 압축 해제한 번들로 수집기 44/44 및 스킬 형식 검사 통과 |
| 설치·발견 | Codex·Claude 설치본의 5파일 해시 일치, 각각 version/changed-summary 실행 성공; Codex CLI 0.162.1 skills/list에서 새 설명과 enabled 확인 |

`--changed`는 현재 Git status를 사용하며 커밋 범위 비교가 아니다. staged 선택에서도
소스는 현재 작업 폴더 내용이다. 삭제된 심볼 정의를 복원하거나 완전한 변경 영향 분석을
수행하지 않는다. 요약 모드는 본문·diff 출력을 줄이며 파일 읽기 자체를 생략하지 않는다.
JSON의 `schema_version`은 1, helper 버전은 5.0.0이다. Git 상태 해석은
[공식 porcelain v1 문서](https://git-scm.com/docs/git-status#_porcelain_format_version_1)를 따른다.

## 도우미 단독 비교

v4의 `9302b66` 코드와 v5 도우미를 같은 임시 fixture에서 비교했다. 각 조건을 1회
워밍업하고 순서를 번갈아 7회씩 실행했다. Python 시작·검색·Git 하위 프로세스를 포함하며,
파일시스템 캐시는 초기화하지 않았다. 모델 호출이나 실제 청구 비용 측정은 아니다.

| 사례 | v4 중앙값 | v5 중앙값 | 시간 변화 |
|---|---:|---:|---:|
| 작은 Python 저장소 | 99.3ms | 99.0ms | -0.3% |
| 반복 import | 101.8ms | 103.4ms | +1.6% |
| 참조 파일 2,000개 | 271.4ms | 293.9ms | +8.3% |
| 파일 한도 1개 | 88.7ms | 90.5ms | +2.1% |
| 같은 Go 패키지 12파일 | 107.3ms | 101.3ms | -5.6% |

다섯 사례 모두 최종 비교의 텍스트 출력과 소스 해시가 동일했고 모든 실행이 성공했다.
큰 참조 사례는 동일한 후보 집합을 비교하기 위해 양쪽 모두 후보 한도를 2,016개로
설정했다. 위 차이는 로컬 소규모 측정이며 전반적인 속도 향상을 입증하지 않는다.
특히 정렬 검색과 추가 기능의 비용이 있으므로 개선 수치만 골라 주장하지 않는다.
원시 샘플·도구 버전·스크립트 해시는 [최종 측정 JSON](v5-benchmark.json)에 있다.

첫 pilot은 기본 200개 후보 한도에서 v4의 병렬 검색 순서가 흔들려 서로 다른 소스를
선택했다. 그 비교는 무효로 처리했고 [pilot 원자료](v5-benchmark-pilot.json)에 `valid: false`로
보존했다. v5의 정렬 검색은 이 과정에서 확인한 재현성 문제를 해결한다.

## 출력량

측정 당시 작업 폴더에서 v5 수집기 자체를 대상으로 같은 소스를 수집했을 때 JSON 출력은
전체 **61,706바이트**, 요약 **7,833바이트**로 **87.3%** 줄었다. 소스 목록·해시는 동일했다.
이는 해당 작업 폴더의 diff를 포함한 한 사례의 출력 바이트 차이다. 토큰·비용 절감이나
동일한 작업 완료 품질을 의미하지 않는다. 요약 이후 본문을 읽으면 추가 출력이 생긴다.
[원자료](v5-summary-output.json)에 대상 파일과 해시를 기록했다.

## 재현

```sh
python3 -B -m unittest evals.test_inspect evals.test_multilang evals.test_v5 evals.test_external_run evals.test_external_summary -v

# v4 동결 번들을 임시 폴더에 푼 뒤 같은 파일 집합으로 비교한다.
baseline_dir=$(mktemp -d)
unzip -q dist/suffice-patch-v4.zip -d "$baseline_dir"
python3 -B evals/bench_inspector.py \
  --before "$baseline_dir/suffice-patch/scripts/collect_context.py" \
  --after scripts/collect_context.py --output /tmp/suffice-v5-benchmark.json \
  --repetitions 7 --warmup 1
```

최종 배포 번들은 지침·Python 도우미 3개·CLI 참조 문서, 총 5파일이다.
[릴리스 해시](../dist/release.json), [v5 고정 ZIP](../dist/suffice-patch-v5.0.0.zip),
[이전 v4 ZIP](../dist/suffice-patch-v4.zip)을 함께 보존한다.
기존 Codex·Claude 설치본은 별도 로컬 백업을 남긴 뒤 해당 5파일만 갱신했다.
설치본 실행과 CLI 발견 결과는 [설치 검증](v5-installation.json)에 기록했다.

검증 환경은 macOS Apple Silicon이다. Linux/Windows, Python 3.9 실제 실행, 새로운
모델 자동 선택률, Claude 모델 호출, 실제 외부 저장소 작업의 성공률·시간·토큰 비교는
수행하지 않았다. 이후 웹사이트 게시 과정의 배포 검증은 이 기능·성능 측정과 별도다.
