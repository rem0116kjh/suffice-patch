# SufficePatch v5: comparison on three public projects

**v5 completed all 9/9 bug-fix attempts successfully; v4 also completed 9/9.** Across nine attempts per version, v5 used 7.27% fewer total tokens and 8.84% less agent time. The prespecified equal-project comparison did not establish consistent token or time improvements.

Evaluation date: 2026-10-15. These were pinned historical upstream bugs repaired in local checkouts, not tests of current upstream releases or production deployments.

## Per-project results

Medians of three attempts per version. Automatic skill selection and successful helper execution were observed in every attempt.

| Project | Success v4 / v5 | v4 total tokens | v5 total tokens | v4 time | v5 time |
|---|---:|---:|---:|---:|---:|
| python-dotenv | 3/3 · 3/3 | 151,161 | 145,102 | 63.9s | 73.4s |
| packaging | 3/3 · 3/3 | 226,724 | 193,253 | 93.6s | 80.5s |
| itsdangerous | 3/3 · 3/3 | 124,943 | 125,527 | 45.0s | 48.1s |

`packaging` improved on both metrics. The median token count fell for `python-dotenv`, but its median time rose. Both medians increased slightly for `itsdangerous`.

## Prespecified equal-project comparison

For each matched task/repetition, compute the v5/v4 ratio. Take the median of three ratios within each project, then the geometric mean across the three projects. This differs from directly dividing the per-version medians above.

| Metric | Equal-project paired change | Descriptive bootstrap 95% interval | Prespecified criterion |
|---|---:|---:|---|
| Total tokens | -5.68% | -14.76% to +0.02% | Not met: At least 10% lower, interval upper bound < 0% |
| Time | -1.36% | -13.98% to +6.97% | Not met: At least 5% lower, interval upper bound < 0% |

Preserved overall and per-project success was also required. With only three projects, these intervals describe variation rather than support broad statistical generalization. The v4 `itsdangerous` times ranged from 40.62 to 99.02 seconds; one long run affected the raw total. A lower time total does not establish a consistent speed improvement.

## Functional verification and conditions

- Both versions: **9/9 successful fixes, 9/9 automatic helper executions and 9/9 protected-file preservation checks**. No failed attempts, timeouts or replacement retries.
- Success required completed agent execution, independent hidden behavioral tests, existing upstream tests, imports from the candidate source and preserved existing tests, user notes and skill files.
- Before model calls, the hidden graders rejected each buggy base and accepted every official reference fix. The independent graders contain 65 checks for dotenv, 202 for packaging and 30 for itsdangerous.
- One historical dotenv test requires GNU `printenv --version`, which macOS BSD `printenv` lacks; it was excluded equally in both versions. The existing packaging skip was preserved.
- Model `gpt-6-astra`, reasoning `low`, Codex CLI `0.162.1`, Python 3.12 and per-project locked dependencies. Three repeats per task and version, 18 sequential runs, schedule seed `20261015`.
- Each run used an independent initial checkout, identical task prompt and only its assigned local skill. Host skills, plugins, memory, web search and agent delegation were disabled.
- Time is the agent process wall time, including its tool use and own tests. It excludes environment setup, harness development, control validation and independent post-run grading.
- Archives, task definitions, graders, plan, runner, initial files and prompts were frozen before model calls. Audits verified hashes, raw usage, model settings, skill isolation and final files.
- Inspection of recorded commands found zero candidates for external reference/evaluator access or additional package installation.

## Scope and limitations

The default automatic selection, collection, editing and verification workflow worked on these tasks. This is evidence of functionality in the tested setting, not proof that v5 always saves tokens or time.

The sample consists of three known historical Python bugs, one model at low reasoning effort and one macOS host. Public-task training contamination, prompt caching and service latency may affect results. There is no skill-disabled arm, real-project multilingual test, production validation or measurement of user intervention time. Because the tasks supplied source paths, they do not establish efficiency gains from v5 Git change selection, JSON or summary modes.
